# PRD：公版项目一键拉取全部仓库最新代码

## 1. 需求背景

当前公版项目存在主仓库及多个子仓库/子模块，开发在同步最新代码时需要逐个进入仓库执行 `pull`，操作繁琐，且当本地存在未提交改动时，容易因为工作区不干净导致拉取失败。

为提升日常同步效率，需要在工具中增加“公版项目一键拉取全部代码仓库最新代码”的能力。

## 2. 需求目标

- 支持对公版项目执行一次操作，自动拉取主仓库及全部子仓库/子模块的最新代码。
- 当仓库存在未提交改动时，先自动 `stash`，拉取完成后再自动恢复。
- 降低人工逐仓处理成本，减少因本地脏工作区导致的更新失败。

## 3. 适用范围

- 适用于公版项目主仓库。
- 覆盖主仓库及其关联的全部子仓库/子模块。

## 4. 用户故事

作为开发人员，我希望在选择公版项目主仓库后，可以一键拉取全部相关仓库的最新代码，这样我不需要逐个仓库手动执行 Git 命令，也不用担心本地未提交改动阻塞更新流程。

## 5. 功能概要

用户在“公版项目”相关工具页面选择主仓库后，点击“一键拉取最新代码”按钮，系统按既定顺序自动执行以下流程：

1. 检查主仓库是否存在未提交改动。
2. 如存在未提交改动，先自动执行 `stash`。
3. 拉取主仓库当前目标分支的最新代码。
4. 读取并遍历全部子仓库/子模块。
5. 对每个子仓库/子模块重复执行：
   - 检查是否存在未提交改动；
   - 如有改动，先 `stash`；
   - 拉取对应分支最新代码；
   - 拉取完成后恢复 `stash`。
6. 全部完成后，输出执行结果日志，包括成功、失败、跳过及异常原因。

## 6. 功能规则

- `stash` 仅在检测到本地有未提交改动时执行。
- 拉取完成后，需尽可能自动恢复此前暂存的改动。
- 若某个仓库不存在可拉取的远程分支，可跳过并记录原因。
- 单个子仓库/子模块拉取失败时，不应影响其他仓库继续执行，但最终结果中需明确标记失败项。
- 若 `stash` 恢复失败，需给出明确提示，便于用户后续手动处理。

## 7. 交互与反馈

- 页面提供明确入口，例如“一键拉取最新代码”按钮。
- 执行过程中展示进度或日志，便于用户了解当前处理到哪个仓库。
- 执行结束后展示汇总结果，至少包括：
  - 成功数量
  - 失败数量
  - 跳过数量
  - 失败原因摘要

## 8. 非功能要求

- 操作过程应尽量自动化，减少用户额外干预。
- 日志信息需可读，便于定位失败原因。
- 当仓库数量较多时，整体流程应保持稳定，避免界面长时间无响应。

## 9. 验收标准

- 选择公版项目主仓库后，用户可以看到“一键拉取最新代码”入口。
- 点击后，系统能够自动处理主仓库及全部子仓库/子模块的更新流程。
- 对于存在未提交改动的仓库，系统会先 `stash`，拉取完成后再恢复改动。
- 对于无远程对应分支或拉取失败的仓库，系统会在结果中明确提示。
- 整个流程结束后，用户可以看到完整的执行日志和结果汇总。

## 10. 备注

本 PRD 为概要版，仅用于说明本次产品需求方向。详细实现细节、界面样式和异常策略可在开发评审阶段进一步补充。
