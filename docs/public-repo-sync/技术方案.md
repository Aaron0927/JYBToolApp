# 技术方案：公版仓库更新

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `PullLatestView` | 展示全部仓库、勾选/全选与更新确认。 |
| `ReposSwitchViewModel` | 读取 `repos.yml`，维护选择状态，更新所选仓库。 |
| `ReposYAMLService` | 解析仓库路径，逐仓 pull 并返回结果。 |
| `ProcessRunner` | 后台执行 Git 命令并返回标准输出或错误。 |

## 读取与检查

读取配置后，工具将 `repos.yml` 声明仓库与配置根目录仓库组合为列表。仓库行使用稳定仓库 ID（scope 与配置路径）关联勾选状态与更新结果，避免同名仓库的状态覆盖。

## 更新流程

1. 从当前列表中筛选用户勾选的仓库。
2. 对每个已选仓库执行当前的自动 stash、`git pull --ff-only`、精确恢复 stash 流程。
3. 单仓失败不终止后续仓库。
4. 保留每仓更新结果；读取和选择阶段不访问远端。

Tag 管理独立于仓库更新，目前仅支持设置并推送 annotated Tag，不读取已有 Tag。分支切换不读取 `repos.yml` 中的 `tag` 字段。

## 测试关注点

- 只更新传入的选中仓库，未选仓库内容保持不变。
- 更新仍遵循 fast-forward、自动 stash 恢复规则，以及 detached HEAD / 无 upstream 跳过行为。
